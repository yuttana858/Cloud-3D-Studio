# Appearance preservation — Cloud 3D Studio 0.5.0

STEP uses OCCT STEPCAF/XCAF rather than a geometry-only transfer. The complete-root check, declared-unit normalization, topology checks and independent STEP process reimport remain required. External file references are rejected before document transfer; the worker never fetches image URLs or arbitrary paths.

Body, face and assembly occurrence colors (linear RGB) and alpha follow the native rendering inheritance rules. Colored STEP is reopened and its style inventory compared. GLB uses the validated tessellation, with material groups under positioned body parents. Original float colors are restored after Trimesh's 8-bit material coercion. Every exported group must retain its material and triangle count; body bounds, area/volume and combined physical units are rechecked. Pole-facet cleanup and all existing limits remain unchanged. Extra material primitives are not mistaken for extra CAD bodies.

`manifest.appearance` is an exact eight-field report with bounded counts and fixed statuses. It contains no source names, RGB values, images, paths, geometry or arbitrary messages. Colors and transparency report STEP/GLB outcomes. Detected render materials report **partial** GLB support (base color, metallic and roughness); other render properties and STEP material fidelity are not promised. Bitmap counts are unknown (`null`, `not_exposed_by_reader`), not falsely reported absent. STL is explicitly `geometry_only`. Old consumers may ignore the new report.

The internal supplied-image path accepts bounded PNG/JPEG bytes and finite per-vertex UV coordinates, embeds the image in GLB, retains pixel alpha and validates reopened pixels and material bindings. It rejects paths/URLs and missing UVs. This is groundwork for a future textured-source adapter, not an image upload or a claim that the current STEP reader extracts bitmap textures. For current artwork/image assets, export a textured GLB from the originating application and use Auto3D's normal GLB import. Images alone cannot reconstruct the original UV mapping.

New Pages connectors negotiate `appearanceProtocol: 1`. An explicit diagnostic may return a **separate** source-only appearance inventory alongside the unchanged nine-field CAD diagnostic. It performs no mesh export, publishes no model, does not reset conversion attempts, extend retention or change ready artifacts, and returns no private report in Modal provider results. Older connectors/workers retain the original diagnostic callback.

The deployment gate additionally requires colored/transparent box, sphere and cone proof. The owned user-API canary checks actual public-fixture GLB factors and alpha whenever the Pages connector advertises appearance support. All fixtures are authored public geometry. Private customer sources must stay within the existing server job pipeline; inspect only the fixed inventory via Auto3D.
